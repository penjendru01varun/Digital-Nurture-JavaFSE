public class Product {
    private int productId;
    private String productName;
    private String category;

    public Product(int productId, String productName, String category) {
        this.productId = productId;
        this.productName = productName;
        this.category = category;
    }

    public int getProductId() {
        return productId;
    }

    public String getProductName() {
        return productName;
    }

    public String getCategory() {
        return category;
    }

    @Override
    public String toString() {
        return "Product [ID=" + productId + ", Name=" + productName + ", Category=" + category + "]";
    }
}

public class LinearSearch {

    public static Product searchById(Product[] products, int targetId) {
        for (int i = 0; i < products.length; i++) {
            if (products[i].getProductId() == targetId) {
                return products[i];
            }
        }
        return null;
    }

    public static Product searchByName(Product[] products, String targetName) {
        for (int i = 0; i < products.length; i++) {
            if (products[i].getProductName().equalsIgnoreCase(targetName)) {
                return products[i];
            }
        }
        return null;
    }

    public static Product searchByCategory(Product[] products, String targetCategory) {
        for (int i = 0; i < products.length; i++) {
            if (products[i].getCategory().equalsIgnoreCase(targetCategory)) {
                return products[i];
            }
        }
        return null;
    }
}

 3. BinarySearch.java


import java.util.Arrays;

public class BinarySearch {

    public static Product searchById(Product[] products, int targetId) {
        int left = 0;
        int right = products.length - 1;

        while (left <= right) {
            int mid = left + (right - left) / 2;

            if (products[mid].getProductId() == targetId) {
                return products[mid];
            }

            if (products[mid].getProductId() < targetId) {
                left = mid + 1;
            } else {
                right = mid - 1;
            }
        }
        return null;
    }

    public static void sortById(Product[] products) {
        Arrays.sort(products, (p1, p2) -> Integer.compare(p1.getProductId(), p2.getProductId()));
    }
}

 1. Big O Notation

Big O notation describes the upper bound of an algorithm's growth rate. It measures how runtime or space requirements increase as input size grows.

| Notation | Name | Description |
|----------|------|-------------|
| O(1) | Constant | Runtime does not change with input size |
| O(log n) | Logarithmic | Runtime grows slowly, halves problem each step |
| O(n) | Linear | Runtime grows proportionally with input size |
| O(n log n) | Linearithmic | Common in efficient sorting algorithms |
| O(n²) | Quadratic | Runtime grows with square of input size |

 2. Time Complexity Comparison

| Aspect | Linear Search | Binary Search |
|--------|---------------|-------------|
| Best Case | O(1) | O(1) |
| Average Case | O(n) | O(log n) |
| Worst Case | O(n) | O(log n) |
| Space Complexity | O(1) | O(1) |

 3. Best, Average, Worst Case Scenarios

 Linear Search
- Best Case: Target element is at index 0 (first position)
- Average Case: Target element is at middle position
- Worst Case: Target element is at last position or not present

 Binary Search
- Best Case: Target element is at middle position on first check
- Average Case: Target element requires multiple halving operations
- Worst Case: Target element is not present, requires maximum halving



 5. Which Algorithm is More Suitable?

Binary Search is MORE SUITABLE for an e-commerce platform.

 Reasons:
1. Scale: E-commerce platforms have millions of products
2. Performance: O(log n) is exponentially faster than O(n)
3. User Experience: Instant search results are expected
4. ID-based Lookups: Product IDs are naturally sortable
5. Database Indexing: Real platforms use B-trees (binary search extension)
 6. Practical Implementation

| Scenario | Recommended Approach |
|----------|---------------------|
| Small catalog (< 1000 products) | Linear search |
| Large catalog (millions of products) | Binary search with sorted arrays |
| Production platform | Hash Map (O(1)) + Database indexing |
| Full-text search | Trie, Inverted Index, Elasticsearch |

 7. Conclusion

For e-commerce platform search:
- Use Binary Search for product ID lookups with sorted data
- Use Hash Maps for O(1) performance in production
- Linear Search is only acceptable for very small datasets
